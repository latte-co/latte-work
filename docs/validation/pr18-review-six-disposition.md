# PR #18 第六轮评审处置

评审：[第六轮报告](https://github.com/latte-co/latte-work/pull/18#issuecomment-6438138830)，评审快照为 `59491a5`。本文件说明本轮修改及保留项，不将未处理的风险计为已修复。

| 评审项 | 处置 |
| --- | --- |
| P2-1 原生 stdout 摄入内存无界 | 保留产品要求的无单条长度上限，不恢复建议中的 128–256 MiB 上限。极大或无换行记录耗尽 host 内存的风险仍在；分页和展示裁剪不能解决摄入风险。需后续单独设计流式解码或隔离解析，本轮未解决。 |
| P2-2 PreviewChange 能力位 | 增加默认关闭的 Hello `change_preview`。客户端仅对当前连接明确支持的主机发出请求；旧 Server、失败重连和断线清除能力，不重试不兼容请求，显示更新提示。 |
| P3-1 发送确认期间取回队列消息 | 禁止确认期间开始编辑；先开始的取回操作会阻止其所属草稿发送，直到请求结束。按草稿计数，导航和迟到结果不会锁住或覆盖其他会话。 |
| P3-2 可选标题写入最多等待 5 秒 | 接受现有有界等待。写入失败不改变已确认的任务结果。直接并发写 stdin 会破坏 JSONL 帧；若要进一步降低延迟，需要统一串行写入器，本轮不增加该重构。 |
| P3-3 崩溃后补发一次标题控制 | 保留恢复行为。`persist: true` 复用原生已有标题，手动名称仍有存储层守卫；不会重发用户任务。 |
| P3-4 success 但没有有效标题 | 保留原名并记录明确 Notice，不伪造标题、不改变任务终态。 |
| P3-5 已手动命名的原生会话恢复 | 适配器接收持久手动名称与恢复标记，跳过自动命名。创建参数只用于新会话；Traex 的既有恢复行为保持不变。 |
